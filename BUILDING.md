# Building Voyager

Voyager is compiled with plain `javac` against the jars of the target modpack - no Gradle, no
mappings step, because NeoForge 1.21.1 mods run on official (Mojang) names.

## What you need

- JDK 21
- A `libs/` folder (not part of the repository - the jars are not ours to redistribute) with:
  - the Minecraft 1.21.1 client jar and its assets jar (the `client-extra` jar of a NeoForge
    install, saved as `libs/mc-extra.jar` - the pack generator validates block ids against it),
  - `neoforge-21.1.x-universal.jar` and `neoforge-21.1.x-client.jar`,
  - `minecolonies-1.1.13xx-1.21.1.jar`, `structurize-1.0.8xx-1.21.1.jar`, `blockui`, `domum-ornamentum`,
  - the libraries Minecraft itself links against: DataFixerUpper, fastutil, Guava, Gson, SLF4J,
    commons-lang3, JOML and the JetBrains annotations jar.
- `stubsrc/` holds two tiny stand-ins (`net.neoforged.api.distmarker.Dist`/`OnlyIn`) for the case
  that your NeoForge jars do not carry them; compile them into `stubs/` first if `javac` complains.
- Python 3 with `nbtlib`, `Pillow`, `numpy` and `scipy` if you want to regenerate the blueprints,
  the suit textures, the hut model or the sounds.

## Compile and package

```bash
javac -encoding UTF-8 --release 21 -proc:none -cp "stubs:libs/*" -d build $(find src -name '*.java')
jar cf voyager-<version>.jar -C build . -C resources .
```

The version lives in `resources/META-INF/neoforge.mods.toml`.

## Generated resources

Nearly everything under `resources/` that is not a texture is generated by the scripts in `tools/`.
They resolve paths relative to the repository (`tools/paths.py`), read third-party jars from
`libs/` (or `$VOYAGER_LIBS`) and write scratch files to `tools/out/`.

| Script | Writes |
|---|---|
| `build_pack.py` | the ten blueprints + `pack.json` of the *Voyager* structure pack (`resources/blueprints/voyager/voyager/`) |
| `gen_trips.py` | the five expedition plans (crafter recipes) and their End loot tables (`data/voyager/crafterrecipes`, `data/voyager/loot_table/recipes`) |
| `gen_research.py` | the research tree and effects (`data/voyager/researches`) plus their lang keys |
| `gen_sounds.py` | the six synthesized sounds (`assets/voyager/sounds/*.ogg`) and `sounds.json` |
| `gen_hut_model.py` | the Departure Point block model (vanilla textures only) |
| `gen_skin.py` | the Voyager suit textures and citizen icons (heads come from MineColonies' Nether Miner textures, so this one needs the MineColonies jar) |
| `gen_astronomer_skin.py` | the astronomer's coat textures and citizen icons (heads come from MineColonies' Student textures) |
| `preview_skin.py` | flat front/back paper-doll previews of a skin into `tools/out/` - a look-check, not a render |

`designs.py` describes every level of both looks as voxels, `voxel.py` turns a design into a
Structurize `.blueprint` (and back, for verification). `build_pack.py` is also the test suite for
the buildings: it rejects unknown block ids (Structurize silently turns them into air), floating
blocks on the Launchpad (with and without the rocket), unsupported ladders, lanterns and doors,
rocket blocks overlapping the structure, and a departure point the Voyager could not walk to.

```bash
cd tools
python3 build_pack.py      # blueprints + pack.json, prints ALL OK when every gate passes
python3 gen_trips.py
python3 gen_research.py
python3 gen_sounds.py
python3 gen_hut_model.py
python3 gen_skin.py
```

`mcrender.py` runs *inside* Blender and renders a design with real block textures (`export_all.py`
packs the designs for it); it was used to approve every level before it was ever built in a world.
